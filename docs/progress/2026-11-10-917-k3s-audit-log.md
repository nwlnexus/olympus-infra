## Decisions

- 2026-11-10: Policy order (first match wins): drop health URLs; log everything by the agent read identities at Metadata; drop node, control-plane, lease and event noise; Metadata for Secrets, ConfigMaps, token reviews and token requests (never bodies); drop other ServiceAccount reads; Request for other writes; Metadata for the rest. Why: agent reads must always be recorded, Secret access must be visible without content, and controller watch noise would swamp the log.
- 2026-11-10: The play stages files and never restarts k3s. Why: a restart of the control plane is run by the owner, one server at a time, with the health gate.
- 2026-11-10: The policy file and log directory are created before the config block is written, and the play asserts both exist. Why: the API server does not start if the policy file is missing.
- 2026-11-10: Done-when check 2 changed from `pgrep` for the flag to the audit log file existing and growing; issue #917 edited. Why: k3s reads the flags from its config file, so they never appear on the command line and the old check would always print 0.
- 2026-11-10: The flag is enabled in the two server group vars in this PR. Why: nothing takes effect until the push play runs and each server restarts, and a server joined later must match.
- 2026-11-10: Not verifiable offline: that k3s accepts the flags and the API server starts with this policy. Proven only at the first server restart; rollback is in the role README.
- 2026-11-10: This file is removed before the olympus-infra PR merges; the task continues in olympus-gitops (log shipping, alert) with a progress file there.
- 2026-11-10: Policy tightened after the verifier's flags: lease and event drops apply only to nodes, ServiceAccounts and control-plane users; kubelet status updates are dropped; machine writes are recorded at Metadata and writes by everyone else at Request. Why: a write by a person must always leave a record, and bodies of machine writes would swamp the log.
