# Upgrade the QNAP CSI plugin v1.6.0 → v1.6.3 (staged)

olympus-infra#165. The owner runs every command that changes the cluster. Every qnap-iscsi volume depends on this
plugin, so the upgrade goes controller first, then one node, then the rest, with checks after each step and a
rollback for each stage. Nothing here hard-codes volume IDs or which node holds which volume: stage 0 derives
them at run time.

## What changes upstream (v1.6.1–v1.6.3)

Read from the release notes and `git diff v1.6.0 v1.6.3` of github.com/qnap-dev/QNAP-CSI-PlugIn:

- **Chart and manifests: image tags only.** `Helm/trident/values.yaml` and `Deploy/` move `qnap-csi`,
  `qnap-csi-operator` and `qnap-csi-backend-qts-sidecar` from `v1.6.0` to `v1.6.3`. `Chart.yaml`:
  `appVersion 1.6.3`, `kubeVersion ">= 1.24.0 <= 1.35"` (was `<= 1.32`; the role still relaxes it). The chart
  version stays `2.0.0` and `Helm/trident/crds/` is unchanged. The other Trident CRDs come from the operator;
  stage 4 compares them before and after.
- **No backend-config change is required.** The upstream doc now spells the CHAP field `useCHAP` (v1.6.0's doc
  said `userCHAP`). Not part of this upgrade.
- **v1.6.1** (node side): stronger filesystem detection before an iSCSI volume is formatted (a device-readiness
  gate before `blkid`, and a second `blkid` on the read-back header). This is the mitigation for
  **QNAP-CSI-PlugIn#50**: v1.6.0 ran `mkfs.ext4` on a populated LUN during a normal re-stage. Until every node
  runs v1.6.3, any re-stage (pod moved, scaled, node drained or rebooted) carries that risk; hence the freeze
  below and the snapshot before the first re-stage of a real volume.
- **v1.6.2**: `trident.qnap.io/IoSyncMode` PVC annotation; QTS 6.0 detection; a fix for "no interface is
  available" on QuTS hero h6.0.0 with several interfaces.
- **v1.6.3**: PVCs without `IoSyncMode` keep the legacy LUN naming and sync settings (a v1.6.2 regression);
  `IoSyncMode: sync` rejected on QTS 6.0+; import of a non-zero LUN; a clone/cross-attach data-safety fix; no more
  `orphaned: true` on every TridentVolume after a `trident-controller` restart (QNAP-CSI-PlugIn#55);
  third-party CVE updates.
- **Not in the notes:** a fix for deleting a volume whose LUN is already gone (`Unmap IscsiTarget fail … -19`).
  The stale records may still fail to delete; stage 6 records the result.
- **Upgrade procedure (upstream):** `helm upgrade qnap-trident Helm/trident/ -n trident`. The operator then
  replaces `trident-controller` and the `trident-node-linux` DaemonSet (every node pod) at once. That is why
  stages 1–3 hold the operator and roll the images by hand, and stage 4 hands control back to the operator.

## How the installation is put together

- Helm release `qnap-trident` in namespace `trident`, installed from the clone the `qnap-csi-bootstrap` role
  made on the k3s primary (`/opt/qnap-csi-plugin`; its `Chart.yaml` carries the `kubeVersion` edit).
- `trident-operator` (Deployment, 1 replica; the chart sets `replicas: 1`) owns `trident-controller`
  (Deployment, strategy Recreate) and `trident-node-linux` (DaemonSet, RollingUpdate maxUnavailable 1) through
  the `TridentOrchestrator` `trident`. The operator writes the DaemonSet's `updateStrategy` itself, so an
  `OnDelete` patch only holds while the operator is scaled to 0.
- Each node pod, when it starts, runs a node cleanup ("Performing node cleanup", "Discovering stale volume
  publications"). It force-unstages any volume it tracks that has no `TridentVolumePublication` on the
  controller. So before any node pod is replaced, every attached volume must have its publication record
  (the `TVP` gate below).

## Conventions

Cluster commands run on the k3s primary (onode-030c31) as root. Paste this once per shell there:

```sh
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
k() { sudo -E k3s kubectl "$@"; }
tctl() { sudo -E /opt/qnap-csi-plugin/bin/linux-amd64/tridentctl -n trident "$@"; }
promq() { k get --raw "/api/v1/namespaces/observability/services/prometheus-server:80/proxy/api/v1/query?query=$(jq -rn --arg q "$1" '$q|@uri')" | jq -r '.data.result[] | "\(.metric.node // "") \(.metric.volume // .metric.alertname // "") \(.value[1])"'; }
nodepod() { k -n trident get pod -l app=node.csi.trident.qnap.io --field-selector spec.nodeName="$1" -o name; }
```

`tctl ... -o json` puts a volume's fields under `.Config` (capital C). `tctl` uses the `tridentctl` in the clone (v1.6.0's ships client 1.05.3; after stage 4 the v1.6.3 one).

**TVP gate** (`TVP`). Every attached qnap-iscsi VolumeAttachment has a matching TridentVolumePublication and
every TridentNode is `clean`:

```sh
tvp() {
  diff <(k -n trident get tridentvolumepublications -o json | jq -r '.items[] | "\(.volumeID) \(.nodeID)"' | sort) \
       <(k get volumeattachment -o json | jq -r '.items[] | select(.spec.attacher=="csi.trident.qnap.io" and .status.attached) | "\(.spec.source.persistentVolumeName) \(.spec.nodeName)"' | sort) \
    && echo "TVP OK: $(k get volumeattachment -o json | jq '[.items[] | select(.spec.attacher=="csi.trident.qnap.io")] | length') publications match"
  k -n trident get tridentnodes -o json | jq -r '.items[] | "\(.metadata.name) \(.publicationState)"' | grep -v ' clean$' || echo "TVP OK: all TridentNodes clean"
}
```

Pass: no diff output and both `TVP OK` lines. **Stop on any diff:** do not replace a node pod while a
publication is missing.

**Cluster check** (`CHECK-C`), after every step:

```sh
k -n trident get deploy,ds,pods -o wide
tctl version
tctl get backend
tctl get volume
tvp
promq 'count by (alertname) (ALERTS{alertstate="firing",alertname=~"Iscsi.*|Multipath.*|StorageTextfile.*|NodeExt4Errors|NodeFilesystemReadOnly|PodVolumeIOErrors|KubePodCrashLooping.*|PrometheusIngestionStopped"})'
promq 'max by (node) (node_csi_staged_volumes{driver="csi.trident.qnap.io"}) - max by (node) (node_iscsi_sessions_logged_in)'
promq 'max by (node, volume) (node_ext4_errors) > 0'
promq 'max by (node, volume) (node_multipath_map_queue_if_no_path) == 0'
promq 'max by (node) (time() - node_storage_textfile_last_run_timestamp_seconds) > 180'
```

Pass: backend `online`; every TridentVolume `online`; `tvp` passes; the alert query returns nothing; the
staged-minus-sessions query returns 0 for every node; the last three queries return nothing.

**Plugin check** (`CHECK-P <node>`), on the primary, after a node pod was replaced. Record
`k -n trident get tridentnode <node> -o jsonpath='{.metadata.resourceVersion}'` just before the delete:

```sh
N=<node>
k get csinode "$N" -o jsonpath='{.spec.drivers[*].name}{"\n"}'
k -n trident get tridentnode "$N" -o jsonpath='{.metadata.resourceVersion} {.publicationState}{"\n"}'
k -n trident logs "$(nodepod "$N")" -c trident-main | grep -E 'Activating CSI frontend|Performing node cleanup|Discovering stale volume publications'
k -n trident logs "$(nodepod "$N")" -c trident-main | grep -E 'no matching volume publication record|Force detached stale'
k -n trident logs "$(nodepod "$N")" -c trident-main | grep -E 'level=(error|fatal)' | tail -5
```

Pass: the CSINode lists `csi.trident.qnap.io`; the TridentNode's resourceVersion moved (the new pod
re-registered) and it is `clean`; the three activation/cleanup lines are there; the fourth command prints
**nothing** (a line there means the cleanup force-detached a volume: stop and check that volume's pod); no new
error lines.

**Node check** (`CHECK-N <node>`), on the node itself over SSH. Read-only host state:

```sh
sudo iscsiadm -m session -P 1 | grep -E 'Target:|iSCSI Session State'
sudo multipathd show maps format "%n %w %N %Q"
findmnt -rn -t ext4 -o TARGET,SOURCE,OPTIONS | grep 'kubernetes.io~csi' | awk '{print $2, substr($3,1,2)}'
grep -H . /sys/fs/ext4/dm-*/errors_count 2>/dev/null
sudo dmesg -T | grep -E 'EXT4-fs (error|warning)|session recovery|I/O error|Detected aborted journal' | tail -5
```

Pass: one `LOGGED_IN` session per staged volume; every map has 1 path (`%N`) and a queueing value that is not
`-`/`off`; every CSI ext4 mount is `rw`; every `errors_count` is 0; no new dmesg lines since the step began.
Also watch the workload pods on the node (`k get pods -A -o wide --field-selector spec.nodeName=<node>`): their
restart counts must not move.

**Scratch volume helpers** (stages 2, 3 and 5). The StorageClass is `Retain`, so deleting goes through the PV:

```sh
scratch_pvc() {
  k create namespace qnap-scratch
  printf '%s\n' 'apiVersion: v1' 'kind: PersistentVolumeClaim' 'metadata: {name: scratch, namespace: qnap-scratch}' \
    'spec: {accessModes: [ReadWriteOnce], storageClassName: qnap-iscsi, resources: {requests: {storage: 1Gi}}}' | k apply -f -
}
scratch_pod() {
  printf '%s\n' 'apiVersion: v1' 'kind: Pod' 'metadata: {name: scratch, namespace: qnap-scratch}' 'spec:' \
    "  nodeSelector: {kubernetes.io/hostname: $1}" '  containers:' '    - name: c' '      image: busybox:1.37' \
    "      command: [sh, -c, '$2 && sleep 3600']" '      volumeMounts: [{name: d, mountPath: /data}]' \
    '  volumes: [{name: d, persistentVolumeClaim: {claimName: scratch}}]' | k apply -f -
  k -n qnap-scratch wait pod/scratch --for=condition=Ready --timeout=5m && k -n qnap-scratch logs scratch
}
scratch_unstage() {
  k -n qnap-scratch delete pod scratch --wait=true
  until ! k get volumeattachment -o jsonpath='{.items[*].spec.source.persistentVolumeName}' | grep -qw "$PV"; do sleep 5; done
  echo "unstaged $PV"
}
scratch_delete() {
  PV=$(k -n qnap-scratch get pvc scratch -o jsonpath='{.spec.volumeName}')
  if [ -z "$PV" ] || [ "$(k get pv "$PV" -o jsonpath='{.spec.claimRef.namespace}/{.spec.claimRef.name}')" != "qnap-scratch/scratch" ]; then
    echo "refusing: PV '$PV' is not the scratch volume"; return 1
  fi
  k -n qnap-scratch delete pod scratch --ignore-not-found --wait=true
  k patch pv "$PV" -p '{"spec":{"persistentVolumeReclaimPolicy":"Delete"}}'
  k -n qnap-scratch delete pvc scratch
  k wait --for=delete pv/"$PV" --timeout=5m
  tctl get volume "$PV"
  k -n trident logs deploy/trident-controller -c storage-api-server --since=10m | grep -E 'Unmap Volume and Iscsi Target Successfully|Delete Iscsi Target Successfully|Delete Volume Successfully'
  k delete namespace qnap-scratch
}
```

`scratch_delete` passes when the PV is gone, `tctl get volume` says not found, and the three log lines are there;
the owner then confirms in the QNAP console (Storage & Snapshots → iSCSI & Fibre Channel) that the LUN and its
target are gone. If the delete fails, do not delete the LUN on the QNAP: keep the record and follow "Runbook:
retire a Retain volume" in olympus-gitops `clusters/olympus/qnap-storage/README.md`.

## Freeze (from stage 1 until stage 4 has passed)

While any node runs v1.6.0 a re-stage carries the #50 risk, and a reboot or drain would also restart node pods
outside this plan. During stages 1–4: **no scaling of qnap-iscsi workloads (except the steps below), no drains,
no reboots, no k3s or OS updates.**

On every k3s node (the list: `k get nodes -o name`), over SSH:

```sh
sudo systemctl stop atlas-updater.timer ansible-pull.timer
systemctl is-active atlas-updater.timer ansible-pull.timer
```

Both print `inactive`. Stopping both matters: an ansible-pull run re-enables the updater timer. Stopped timers
come back after a reboot, which the freeze forbids anyway. Pause the descheduler, which evicts pods every 30 min
(an eviction re-stages a volume):

```sh
flux suspend helmrelease descheduler -n descheduler
k -n descheduler patch cronjob descheduler -p '{"spec":{"suspend":true}}'
```

Stage 7 lifts the freeze.

are not touched.


Verify: `CHECK-C` (`tvp` must pass: the new controller loaded every publication), and:

- `tctl version` shows server 1.06.3.
- The volume and backend records are what they were (in particular every `internalName`, against the v1.6.2
  LUN-naming regression; `orphaned` still true only on the `stale.txt` volumes, the #55 fix):

  ```sh
  diff "$B/tvol-before.json" <(tctl get volume -o json | jq -S '[.items[] | {name: .Config.name, internalName: .Config.internalName, size: .Config.size, state, orphaned, backendUUID}]') && echo "volumes unchanged"
  ```

## Stage 4 — hand control back to the operator (the point of no pause)

Run `tvp` and `CHECK-C` first. From the `helm upgrade` on, there is no pause: the chart's operator Deployment has
`replicas: 1`, so Helm brings the operator back itself, and it reinstalls everything at once.

Put the clone on the pin (the commit of v1.6.3, as in `roles/qnap-csi-bootstrap/defaults/main.yml`) and upgrade.
`--reset-values` is required: without new values, `helm upgrade` reuses the release's stored values (revision 1
holds the QNAP admin and CHAP secrets the old role passed) and would copy them into revision 2.

```sh
cd /opt/qnap-csi-plugin
sudo git checkout -- Helm/trident/Chart.yaml
sudo git fetch --tags origin
sudo git checkout 3e4e730f15fd3d283202b3edf4f7c169ea5b0c66
sudo sed -i 's/^kubeVersion:.*/kubeVersion: ">= 1.24.0"/' Helm/trident/Chart.yaml
sudo -E helm upgrade qnap-trident Helm/trident -n trident --reset-values
k -n trident rollout status deploy/trident-operator --timeout=5m
sudo -E helm get values qnap-trident -n trident
k -n trident get tridentorchestrator trident -o jsonpath='{.status.status} {.status.version} {.spec.tridentImage}{"\n"}'
```

`helm get values` must print `USER-SUPPLIED VALUES: null`. If the operator is still at 0 replicas after the
upgrade, `k -n trident scale deploy/trident-operator --replicas=1`.

Expected: the operator (v1.6.3) finds the installation labelled `trident_version v1.06.0` and reinstalls it at
v1.6.3. It replaces `trident-controller` and the DaemonSet, so every node pod restarts at about the same time, on
the image it already runs. Mounts stay (the operator did the same at the k3s 1.35 hop on 2026-10-04, and the
node pods all restarted at the 2026-11-26 boot). The orchestrator ends `Installed`, version `v1.06.3`.

Verify: `CHECK-C` (`tvp` included); the DaemonSet's `updateStrategy` is RollingUpdate again; every pod image is
v1.6.3; `CHECK-P` on every node (no `Force detached stale` anywhere); `CHECK-N` on the nodes with volumes; and the
Trident CRDs:

```sh
k get crd -o json | jq -r '.items[] | select(.spec.group=="trident.qnap.io") | "\(.metadata.name) \(.metadata.generation) \([.spec.versions[].name]|join(","))"' | diff "$B/crds-before.txt" - && echo "CRDs unchanged"
```

A changed generation is fine if the served versions are the same; a removed version is a stop.

After stage 4, **fix forward** rather than roll back. `helm rollback qnap-trident 1 -n trident` exists, but it is
an untested all-at-once downgrade (every node pod at once, back to v1.6.0), it restores the #50 exposure, and it
restores the stored QNAP credentials in the release. Use it only if v1.6.3 cannot serve volumes at all, then put
the clone back (`sudo git checkout -- Helm/trident/Chart.yaml && sudo git checkout v1.6.0`, re-apply the `sed`).
